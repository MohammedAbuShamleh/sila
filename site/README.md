# صِلة — الموقع التعريفي

صفحة واحدة عربية RTL: Vite + React + TypeScript + Tailwind v3. تُبنى static وتُنشر على GitHub Pages.

## التشغيل

من داخل `site/`؛ للموقع `package.json` وملف قفل خاصّان به، لا يمسّهما المحرّك ولا يمسّ أوامره:

```bash
npm install
npm run dev       # معاينة التطوير
npm run build     # البناء إلى dist/
npm run preview   # معاينة نسخة البناء
```

`npm run build` يمرّ بأربع خطوات: فحص الأنواع (`tsc`)، ثم بناء الواجهة، ثم بناء نسخة خادم مؤقتة،
ثم `scripts/prerender.mjs` الذي يكتب الصفحة مرسومةً داخل `dist/index.html`. فتصل الصفحة جاهزة للعرض
قبل تحميل JavaScript، ثم يلتقطها React (hydration) دون أن يعيد رسمها.

## النشر

`.github/workflows/pages.yml` في جذر المستودع يبني `site/` وينشره على GitHub Pages عند كل دفع إلى `main`
يمسّ `site/` أو الملف نفسه (أو يدوياً من تبويب Actions). إعداد لمرة واحدة في المستودع: **Settings ← Pages ← Source: GitHub Actions**.

المستودع مستودع مشروع، فالصفحة تُنشر تحت `/<اسم المستودع>/` لا في الجذر. سير العمل يأخذ هذا المسار من
`actions/configure-pages` ويمرّره إلى البناء في `PAGES_BASE_PATH`، و`vite.config.ts` يجعله أساس الأصول: `/sila/assets/…`
لمستودع اسمه `sila`، و`/assets/…` إن نُقل إلى مستودع مستخدم أو نطاق خاص. وبلا المتغيّر (التطوير والبناء المحلي والمعاينة)
يبقى الأساس نسبياً (`./`).

## أين النص

كل النص العربي في `src/content.ts` وحده. `<title>` ووصف الصفحة يُحقنان منه في `index.html` وقت البناء (`vite.config.ts`).
الكود والمعرّفات والتعليقات بالإنجليزية.

## الحركة

الحركة تضيف ولا يتوقف عليها الظهور: حالة السكون لكل عنصر هي حالته النهائية المقروءة، ولا شيء يختفي
في انتظار سكربت. حركات البطل (سطور العنوان والخط الأفقي) رسوم CSS تبدأ مع التحميل. أما الدخول عند التمرير
فلا يبدأ إلا حين يُثبت المراقِب أن العنصر كان خارج الشاشة ثم دخلها (`data-motion="enter"`، انظر `useInView`).
فإن لم يُبلغ المراقِب أبداً بقيت الصفحة كاملة: الخلفيات في أماكنها، والنص ظاهر، والأرقام بقيمها الحقيقية.
البطاقات تحفظ سطحها ثابتاً ويتحرك محتواها وحده. كل حركة CSS داخل `@media (prefers-reduced-motion: no-preference)`،
والحركة التي يقودها JS (الوهج والعدّاد) تفحص `prefersReducedMotion()`. مراقِب واحد مشترك لكل الصفحة.

أصناف الموقع (`.hero` و`.how` و`.numbers`…) في `src/index.css` خارج `@layer components` عمداً: Tailwind يُسقط
الأصناف الطبقية التي لا يجدها في الملفات التي فحصها، فتختفي خلفية قسم كامل بلا خطأ.

## خط العناوين والأرقام: Thmanyah Sans (محلي فقط)

خط ثمانية للعناوين والأرقام واسم «صِلة» في الترويسة والتذييل (`font-display` في `tailwind.config.js`)، وملفاته في
`public/fonts/thmanyah/` بصيغة WOFF2 كما وردت دون تعديل. يُعرَّف منها وزنان فقط، 400 و700، ويُحمَّل الـBold مسبقاً
لأن عنوان البطل يبدأ به. أما نص الصفحة فبـIBM Plex Sans Arabic، والأوامر بـIBM Plex Mono، من Google Fonts دائماً.
رخصة الخط تمنع استضافة ملفاته أو إتاحتها للتنزيل، والتضمين في المواقع منه. لذلك:

- المجلد في `.gitignore` جذر المستودع: لا يدخل المستودع، فلا ينشره أي دفع أو سير عمل.
- `vite.config.ts` لا يعرّف الخط إلا إن وُجدت ملفاته. بدونها (نسخة جديدة من المستودع، أو بناء GitHub) يأخذ
  Reem Kufi من Google Fonts مكانه في العناوين والأرقام تلقائياً، بلا رابط مكسور.
- `npm run build` محلياً ينسخ ملفات الخط الخمسة كلها إلى `dist/fonts/`، لا الوزنين المعرّفين وحدهما: لا ترفع `dist`
  يدوياً إلى أي مكان.
- للنشر به يلزم إذن مكتوب من ثمانية (ask@thmanyah.com) يغطي موقعاً عاماً ومستودعاً عاماً.

بعد أي تعديل على `tailwind.config.js` أعد تشغيل `npm run dev`: Tailwind يحتفظ بالإعداد في ذاكرته حتى يُعاد تشغيله.

## خادم التطوير

`vite.config.ts` يراقب الملفات بالاستطلاع (polling) لا بتنبيهات النظام: على هذا الجهاز أسقطت التنبيهات
تعديلات وملفات جديدة، فظل خادم تطوير يقدّم وحدات قديمة وCSS بلا أقسام. إن بدا ما يعرضه خادم قديماً، أعد تشغيل `npm run dev`.

## ما تحقّقتُ منه

- **التباين:** حُسبت الخلفية تحت كل سطر نص في الصفحة (التدرّجات + البطاقات الشفافة + الوهج بأقصى إزاحة
  + الخطوط البيضاء في أسوأ حالاتها) على 13 مقاساً من 360×640 إلى 2560×1440. لا فشل في أي قسم.
  فقرة البطل تبقى على `#14502F` أو أدكن (≤ 55% من التدرّج، والمحطة عند 62%). وبقيت كذلك حين أُجبرت الصفحة
  على Segoe UI وTahoma لمحاكاة لحظة ما قبل تحميل الخطوط.
- **الأبيض على `#3B8A55`:** لا يقع عليه نص عادي في أي مقاس. في شريط الأرقام يبقى `#1B5C36` حتى 60%،
  وتبقى الأرقام بعيدة عن الطرف الفاتح (عمود واحد على الهاتف، عمودان متوسطاً، صف بعرض 60rem إلى اليمين في الشاشات العريضة).
- **فشل المراقِب:** جُرِّبت الصفحة ومراقِب يعمل، ومراقِب موجود لا يُبلغ أبداً، وبلا مراقِب إطلاقاً.
  في الثلاث: 0 من 47 كتلة نص مخفية قبل التمرير وبعده، وخلفيات الأقسام والبطاقات حاضرة، والأرقام بقيمها الحقيقية.
- **الحركة:** عند الدخول يتحرك محتوى البطاقة الأولى ثم الثانية بعد 150ms، والعدّاد يبقى على قيمته حتى يدخل
  الشريط ثم يصعد من الصفر بأرقام عربية (بلغ ٨٧ من ١٣٠ بعد 450ms). ومع `prefers-reduced-motion: reduce` لا تعمل أي حركة.
- **التفاعل:** الخط السفلي للروابط يُرسم من اليمين عند المرور، وحلقة التركيز ظاهرة بلوحة المفاتيح على كل عنصر،
  وروابط الترويسة تنزلق إلى أقسامها.
- **زر النسخ:** نقرة حقيقية ← «نُسخ ✓» ثم يعود بعد ثانيتين، وعرض الزر ثابت في الحالتين.
- **Lighthouse 12.8**، بإعداد خط سابق لا بالحالي: يومها كان خط ثمانية لنص الصفحة، بأوزان 400/500/700
  وتحميل مسبق لـRegular، وبديله في النسخة المنشورة IBM Plex Sans Arabic. الإعداد الحالي (العناوين والأرقام،
  وزنان، تحميل مسبق لـBold، وReem Kufi بديلاً من Google Fonts) لم يُقَس. على نسخة البناء بخادم يضغط gzip كما يفعل GitHub Pages:
  الهاتف — أداء 97–99 (يتذبذب بين التشغيلات في زمن الخيط الرئيسي)، إمكانية وصول 100، أفضل ممارسات 100، SEO 100.
  الحاسوب — 100 في الأربعة. (هذه أرقام النسخة المنشورة يومها، بلا ملفات ثمانية.)
  ومع ملفات ثمانية محلياً، أربع جولات متناوبة على الشاحن:
  وسيط الأداء 95.5 مقابل 100 بدونه، وLCP ‏2.5s مقابل 1.4s، وCLS ‏0.002. الكلفة كلها تقريباً في FCP/LCP:
  كل ملف خط (~78KB) يضيف نحو 0.35s تحت شبكة الهاتف البطيئة التي يحاكيها Lighthouse.
  قِس دائماً والجهاز على الشاحن: على البطارية ينزل المعالج إلى ~1GHz وتفقد الأرقام معناها.

## لم يُختبر حياً

- **parallax الوهج.** الكود مكتوب والإزاحة مقصوصة عند ±12px، لكن الحركة نفسها لم تُرَ: نافذة المعاينة كانت
  مخفية فتوقّف `requestAnimationFrame`. للاختبار: حرّك الفأرة فوق البطل ← يزيح الوهج 12px على الأكثر
  نحو المؤشر، ويعود إلى المركز عند مغادرة النافذة. لا حركة على شاشات اللمس ولا مع تقليل الحركة.
- **مسارا النسخ الاحتياطيان.** `execCommand` ثم تحديد الأمر للنسخ اليدوي لم يُستدعيا في استخدام حقيقي: في المتصفح
  الذي جرت فيه الاختبارات نجح النسخ بالواجهة الحديثة. استُدعيا مرة واحدة في 2026-10-07، لا باستخدام حقيقي بل بنقرة
  مبرمجة (`click()` من سكربت، بلا تفعيل من مستخدم) في متصفح معاينة يرفض الكتابة في الحافظة: رفضت الواجهة الحديثة،
  ولم ينجح `execCommand`، فحُدِّد الأمر `npm install -g sila-memory` للنسخ اليدوي. نقرة حقيقية تصل إليهما لم تُجرَّب.
- **متصفحات غير Chromium.** كل الاختبارات جرت في Edge. Safari (منه `overflow: clip` و`svh`) وFirefox لم يُفتحا.
- **قارئ شاشة حقيقي.** البنية مفحوصة (عناوين، أسماء، قيم العدّاد النهائية للقارئ)، لكن لم يُجرَّب NVDA أو VoiceOver.
- **سير عمل النشر.** شُغِّل على GitHub في 2026-10-07: بُني الموقع ونُشر في 36 ثانية على
  [mohammedabushamleh.github.io/sila](https://mohammedabushamleh.github.io/sila/). والصفحة المنشورة تطلب أصولها من
  `/sila/assets/`، فـ`configure-pages` أعطى `base_path` القيمة `/sila` كما جُرِّب محلياً في 2026-10-06.
